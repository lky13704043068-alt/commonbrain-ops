# 从“多 Agent”到“可审计 Agent 系统”：CommonBrain Ops 的共享事实与模型路由设计

## 摘要

多个 Agent 同时工作时，最容易被忽略的问题不是模型能力，而是事实、权限、成本和故障状态无法统一。CommonBrain Ops 将 Agent 运行拆成共享事实层、模型路由层和审计运维层，使同一任务可以被复现、比较和恢复。

## 1. 共享事实层

共享事实层不把所有对话简单拼成一个超长上下文，而是把可复用信息结构化为事件、决定、任务状态和来源：

```json
{
  "type": "decision",
  "subject": "campaign-plan",
  "summary": "待人工确认的活动执行方案",
  "source_refs": ["knowledge://policy/example"],
  "owner": "role:operator",
  "status": "pending_review",
  "updated_at": "2026-08-18T00:00:00Z"
}
```

Agent 读取事实时必须带来源和更新时间；当两个事实冲突时，系统保留冲突记录并要求人工确认，而不是静默覆盖旧信息。

## 2. 模型路由层

路由器根据任务类型、可用额度、历史可靠性、延迟和预算选择候选模型。一次路由决策至少应记录：

- 请求类型和风险等级；
- 候选模型与淘汰原因；
- 实际模型、Token 和延迟；
- 工具调用结果与错误类型；
- 是否发生重试、熔断或降级。

这样可以把“模型感觉更好”转化为可重复的任务评测，并避免因为某个免费额度耗尽而让整条业务流程中断。

## 3. 评测与上线闸门

最小评测集覆盖知识问答、业务工作流、工具调用、权限/隐私和供应商故障五类任务。上线前分别记录基线和目标，不把目标指标写成已完成结果。每次路由策略、提示词、模型版本或工具权限变化后，重新执行回归测试。

## 4. 安全边界

公开 Demo 使用合成或脱敏数据；密钥只通过环境变量或密钥管理器提供；高风险工具调用需要人工确认；审计日志记录来源、模型、工具结果和资源消耗。Hermes Agent、OpenClaw 及其他组件按其原许可证保留声明，自有模块与第三方依赖分开管理。

## 5. 下一步验证

项目将通过国产模型/API 兼容测试、30–50 个脱敏任务、并发/故障注入、越权和提示注入测试，形成可公开复现的基准报告。当前文档描述的是设计和计划，实测结果将在对应版本发布后补充。
